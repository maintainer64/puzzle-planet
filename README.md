# Puzzle Planet

Анонимная многопользовательская веб-игра о наблюдениях, логике и поиске скрытой планеты. До четырёх исследователей, общее интерактивное небо, приватные планшеты дедукции, заметки и журналы. Есть стандартный режим на 12 секторов, экспертный на 18 и одиночная тренировка без бота.

Регистрация, ChatGPT, внешний игровой сервис и отдельная база не нужны. Один контейнер содержит Node.js-сервер и собранный React-интерфейс; SQLite хранится в Docker volume. Карта и чужие ответы не передаются клиентам. Анимации можно отключить; учитывается `prefers-reduced-motion`.

## Запуск из исходников

```sh
git clone git@github.com:maintainer64/puzzle-planet.git
cd puzzle-planet
docker compose up -d --build --wait
```

Откройте **http://localhost:8080**. Остановка: `docker compose down`. База и активные партии сохраняются в volume `puzzle-data`; не добавляйте `-v`, если не хотите удалить их.

## Запуск опубликованного образа

```sh
docker compose pull
docker compose up -d --no-build --wait
```

Образ: `ghcr.io/maintainer64/puzzle-planet:latest`, платформы `linux/amd64` и `linux/arm64`. Можно закрепить версию: `IMAGE_TAG=1.0.0 docker compose up -d --no-build --wait` (сначала `IMAGE_TAG=1.0.0 docker compose pull`).

По умолчанию порт доступен только локально. Для доступа с других компьютеров:

```sh
BIND_ADDRESS=0.0.0.0 PORT=8080 docker compose up -d --build --wait
```

На сервере рекомендуем HTTPS reverse proxy. Для него задайте `.env`:

```dotenv
PUBLIC_ORIGIN=https://puzzle.example.com
COOKIE_SECURE=true
```

`PUBLIC_ORIGIN` — внешний origin без пути и конечного `/`; proxy должен сохранять cookie и направлять `/api` и статику в один сервис. Приложение не доверяет заголовкам идентичности. `COOKIE_SECURE=true` используйте только при HTTPS, иначе браузер не отправит cookie. Остальные параметры — в `.env.example`.

## Анонимные игроки и срок комнаты

- Cookie `puzzle_player` содержит случайный 256-битный ключ, доступный только серверу (`HttpOnly`, `SameSite=Lax`). Результаты принадлежат этому браузеру, а не выбранному имени. Разные браузеры/профили — разные игроки.
- Перезагрузка и перезапуск контейнера не теряют место в комнате. Очистка cookie или другой браузер создаёт нового игрока; переноса профиля между устройствами нет.
- Комната доступна **24 часа с момента создания**. Запуск партии, ходы и опросы не продлевают срок. После таймаута удаляются код, состояние партии, журнал и личные заметки.
- Доступ блокируется сразу по достижении таймаута; физическая очистка выполняется при запуске сервера и каждую минуту. Завершённые партии живут до того же срока.
- Известный код позволяет присоединиться только до начала партии и при наличии места. Он не открывает чужой планшет или закрытую карту. Не публикуйте код, если хотите играть только с друзьями.

В интерфейсе есть локальная помощь по игре, время окончания комнаты и подтверждение поиска X. Партия сохраняется автоматически; личные заметки — кнопкой «Сохранить».

## Разработка и тесты

Node.js 24.13+:

```sh
npm ci
npm run dev
```

UI: http://127.0.0.1:5176; API: http://127.0.0.1:3000. Vite проксирует `/api` в Node-сервер. Для изменений серверного кода перезапустите `npm run dev`.

```sh
npm test
npm run typecheck
npm run build
npm start
# В другом терминале:
node scripts/api-smoke.mjs http://127.0.0.1:3000
node scripts/browser-smoke.mjs http://127.0.0.1:3000
```

Browser smoke использует локальный Chrome, путь можно задать через `CHROME_BINARY`. Скриншоты сохраняются в игнорируемую папку `outputs/`.

Для запущенного Compose: `node scripts/persistence-smoke.mjs http://127.0.0.1:8080 puzzle-planet`. Тест перезапускает только сервис `app` указанного проекта и проверяет, что игрок, заметки и срок комнаты сохранились в volume.

Тесты покрывают генерацию карт, приватность ответов, очередность, теории, очки, финал, cookie-изоляцию, истечение ровно через 24 часа, удаление данных и сохранение SQLite после перезапуска. API smoke проверяет двух настоящих анонимных игроков и конфликты одновременных ходов. Обновления комнаты используют атомарный `UPDATE ... WHERE version = ?`; устаревший запрос возвращает HTTP 409.

## CI и публикация

- Push в `main` и pull request: unit-тесты, TypeScript, сборка, Docker build и API smoke через настоящий Docker Compose.
- Push `v1.0.0`: после успешных проверок публикуются образы `1.0.0` и `latest` в GHCR.
- Push `v1.1.0-rc.1`: публикуется только `1.1.0-rc.1`, **без изменения `latest`**.
- Ветка `main` и pull request **никогда не публикуют `latest`**. Версии actions закреплены по SHA; Dependabot следит за зависимостями, actions и базовым образом.

```sh
git tag v1.0.0
git push origin v1.0.0
```

Один экземпляр сервера обслуживает SQLite; распределённая работа нескольких реплик с общей базой не поддерживается. Фоновая очистка комнат не является гарантией немедленного физического стирания резервных копий/дисковых снимков.
